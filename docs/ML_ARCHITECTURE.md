### 3.1 Dataset snapshot

- **Decide:** which Kaggle dataset version is pinned through the Kaggle API, how the snapshot hash is computed and recorded, and the refresh policy (bumping the pinned version).
- **Decision (2026-10-17):** the pinned dataset is `davidcariboo/player-scores` at version 679. On 2026-10-17, Kaggle's dataset metadata reported `currentVersionNumber = 679` (last updated 2026-09-05). The dataset description says updates are paused and the data is current to 2026-07-06: no games after 2026-07-06, no appearances after 2026-06-28, no player valuations after 2026-06-12, and no 2026/27 squads. Ingest records the snapshot in `ml/data/ingest/_snapshot.json` with the fields `dataset`, `version`, `handle`, `ingested_at` (the UTC start time of the run in ISO 8601 with `Z`; the files may come from kagglehub's cache), `snapshot_sha256`, `tool_versions` (`kagglehub`, `pyarrow`), and `tables`, keyed by table name, each with `source_file`, `parquet_file`, `sha256`, `rows`, `columns`, and `column_names` (in source order). `snapshot_sha256` is built as follows: for each source CSV, one line made of the lowercase hex SHA-256 of the file bytes, two spaces, the file name relative to the dataset root (`/` separators), and `\n`; sort the lines by file name in Unicode code-point order, join them, encode as UTF-8, and take the SHA-256. The hash depends only on file names and contents. For version 679 it is `94f42930f5d50d76f5226f64bd2b9e4c70552e110ad28743b5edce4041c8b1c1`. To refresh, change `DEFAULT_KAGGLE_DATASET_VERSION` in `ml/src/delphos_ml/config.py` or set `DELPHOS_KAGGLE_DATASET_VERSION`, as a deliberate commit. A full ingest of version 679 peaks at 703 MiB of memory, so at least 1 GiB of free RAM is recommended. It uses about 873 MiB of disk for the kagglehub cache (`~/.cache/kagglehub`) and about 228 MiB for `ml/data/ingest/`. A cached run takes about 10 s and the first download about 33 s.
- **Why it matters:** the dataset version and snapshot hash go into every manifest, and reproducibility of published results depends on it.
- **Needed by:** week 3 (ingest).

### 3.2 Data scope and attribute selection

- **Decide:** which dataset tables and columns enter the pipeline, and the population filters (competitions, seasons, minimum minutes played, how goalkeepers are handled).
- **Inputs known so far:** version 679 has 12 tables (rows / columns): appearances 1,894,350 / 13; club_games 177,916 / 11; clubs 796 / 17; competitions 65 / 11; countries 124 / 8; game_events 1,274,469 / 11; game_lineups 3,179,016 / 10; games 88,958 / 23; national_teams 124 / 17; player_valuations 656,301 / 6; players 50,149 / 26; transfers 175,165 / 10. That is 7,497,433 rows, about 220 MiB of Parquet from 873 MiB of source CSV.
- **Decision (2026-10-28):**
  1. **Included and excluded tables:** 9 of the 12 tables enter `clean`: `appearances`, `club_games`, `clubs`, `competitions`, `game_lineups`, `games`, `player_valuations`, `players`, and `transfers`. Three tables are excluded: `countries` and `national_teams` (the country and confederation fields needed downstream already live on `competitions` and `players`, and `national_teams` is a static 2026 snapshot with 100% null `coach_name`), and `game_events` (of its 1,274,469 rows, 49.54% are `Substitutions` with 93,157 empty descriptions, 29.95% are `Cards` already counted in `appearances`, and 1.07% are `Shootout` tiebreaker kicks that do not count as official match goals; within the remaining 247,803 `Goals` rows, 6,729 are own goals, 15,387 games fall outside `appearances` coverage, and isolating the 21,898 penalty goals, 8.84% of goal events, requires substring matching across 8,931 free-text `description` variants and would add a penalty-breakdown input to live what-if scoring. Penalty-taker inflation on `goals` is recorded as a known limitation in [docs/REPORT_NOTES.md](REPORT_NOTES.md)).
  2. **Competitions filter:** `competitions` has 65 rows and 31 `type == 'domestic_league'` rows, 17 of which (`BRA1`, `ARG1`, `MLS1`, `JAP1`, `PL1`, `MEX1`, `TS1`, `RO1`, `C1`, `SER1`, `SE1`, `SA1`, `A1`, `NO1`, `KR1`, `RSK1`, `AUS1`) were added in 2024 to 2025 with `0` rows in `appearances`. Valuation rows are restricted to clubs in the closed set of **14 European first-tier domestic leagues with full `appearances` coverage**: `IT1`, `ES1`, `GB1`, `FR1`, `TR1`, `L1`, `NL1`, `PO1`, `BE1`, `RU1`, `GR1`, `SC1`, `UKR1`, and `DK1` (30.91 and 30.90 appearances per game in 2024 and 2025). Trailing club performance aggregates appearances and lineups across all tracked club competitions: those 14 domestic leagues, domestic cups (`type == 'domestic_cup'`), domestic super cups and playoffs, and UEFA club competitions (`type == 'international_cup'` or `sub_type` prefixed with `uefa_`, noting that `UCOL` main-stage games carry 0 `appearances` rows in v679). `national_team_competition` rows are excluded.
  3. **Season window:** seasons `2017` through `2025` (`2017/18` to `2025/26`), assigning any date to season start year `year` when `month >= 7` and `year - 1` otherwise (97.82% agreement with `games.season`). Starting in `2017` keeps the post-2017 transfer-fee regime, guarantees complete `game_lineups` density (`>= 34.61` rows per game since `2013`), and gives every `2017` row a full 365-day lookback.
  4. **Position exclusion filter:** exclude `players.position == 'Goalkeeper'` (5,828 players and 72,205 valuation rows; active goalkeepers average 0.00014 goals/90 and 0.00273 assists/90, and no table records saves, shots faced, or goals prevented) and `players.position == 'Missing'` (586 players). Retain `Defender`, `Midfield`, and `Attack` (failing fast if any unexpected `position` token appears). `clean` drops `Goalkeeper` and `Missing` rows directly on `players`, whereas all 65 `competitions`, pre-`2017` match rows needed for lookbacks, and all `656,300` positive `player_valuations` rows remain in `ml/data/clean/` for `transform` to filter at join and window time.
  5. **Minimum minutes and Empirical Bayes smoothing:** require `>= 180` trailing 365-day minutes (`47,350` player-seasons across `14,688` distinct players, measured over `ml/data/clean/`), avoiding the 30.1% sample loss of a `900`-minute cutoff (`33,113` rows) that drops emerging squad players. To stabilize noisy per-90 rates on low-minute rows without discarding them, `transform` applies Empirical Bayes pad-90s shrinkage `r_hat = (count + m * prior_pos) / ((minutes / 90) + m)` with `m = 5` (450 minutes of positional prior fit on `train` seasons only, which cuts next-season `G+A/90` RMSE by 42.4%, from `0.3143` to `0.1809`, across `2,378` low-to-regular transitions) alongside unsmoothed volume features (`minutes_played`, `starter_ratio`).
- **Why it matters:** it defines what every later stage sees. The exploratory analysis (`analysis/eda.py`) produced the evidence and closes the baseline's data-selection phase ([docs/CONTEXT.md](CONTEXT.md) §3, phase 2).
- **Needed by:** week 3 (exploratory analysis).

### 3.3 Unit of analysis

- **Decide:** what one row represents, for example a player at a valuation date with performance aggregated over a fixed window before that date, and the window length.
- **Decision (2026-10-28):** **Option A (end-of-season player-season snapshot)** is adopted for modeling and publishing. One row is a `(player_id, season)` pair anchored on the player's latest `player_valuations.date` (`as_of_date`) within that July 1 to June 30 season, with target `market_value_in_eur` at `as_of_date` and performance features from `appearances`, `club_games`, and `game_lineups` aggregated over the trailing 365-day window `(as_of_date - 365 days, as_of_date]`, half-open so that the window holds exactly 365 days of matches. Across seasons `2017` to `2025` in the 14 covered European leagues, Option A produces `107,395` outfield snapshots before the minutes floor and `47,350` rows (`14,688` players) at `>= 180` minutes, measured over `ml/data/clean/` after the §3.5 row drops. The exploratory analysis over `ml/data/ingest/` reported `107,456` / `47,359` / `14,692`; the difference is the `4` outfield players whose `date_of_birth` is null and whom `clean` drops under §3.5, worth `61` snapshots before the floor and `9` rows after it. Option B (keeping all `235,594` raw valuation updates in `2017` to `2025`) is rejected because 30.86% of `(player_id, season)` pairs receive 3 to 6 updates within the same season, overweighting star and recently transferred players and introducing serial autocorrelation across consecutive snapshots. For the separate market-inefficiency dataset (§3.12), one row is a paid outfield transfer in `transfers` (`transfer_fee > 0`, seasons `2017` to `2025`, involving at least one club in the 14 covered leagues, with pre-transfer valuation and `>= 180` minutes in `[transfer_date - 365 days, transfer_date - 1 day]`; `5,325` rows).
- **Why it matters:** the target, the features, the temporal-leakage policy, and every published row depend on it.
- **Needed by:** week 4 (clean, transform).

### 3.4 Temporal leakage policy

- **Decide:** point-in-time discipline for transfer and valuation history — which columns are known at prediction time, and how splits respect time.
- **Decision (2026-10-28, refined 2026-10-29):**
  1. **Banned static snapshot columns:** every mutable 2026-snapshot field on `players` (`current_club_id`, `current_club_name`, `current_club_domestic_competition_id`, `contract_expiration_date`, `market_value_in_eur`, `highest_market_value_in_eur`, `international_caps`, `international_goals`, `current_national_team_id`, `agent_name`, `last_season`), `appearances.player_current_club_id` (static 2026 club alongside point-in-time `player_club_id`), and every squad-aggregate or scraper column on `clubs` (`total_market_value`, `squad_size`, `average_age`, `foreigners_number`, `foreigners_percentage`, `national_team_players`, `net_transfer_record`, `coach_name`, `last_season`, `filename`) is forbidden as a model feature and physically dropped in `clean` before writing `ml/data/clean/`. Across `347,548` historical valuation rows (`2017` to `2023`), `players.current_club_id` disagrees with the point-in-time club on 47.47% of rows, `players.highest_market_value_in_eur` exceeds point-in-time market value on 88.49%, and non-null `players.contract_expiration_date` falls in 2025 or later on 71.84%.
  2. **Allowed point-in-time sources:** club and domestic competition at `as_of_date` come only from `player_valuations.current_club_id` and `player_valuations.player_club_domestic_competition_id` (`clubs` is joined only for static `name` and `club_code` display metadata). Only biographical fields come from `players`: `player_id`, `name`, `date_of_birth` (used to compute `age = (as_of_date - date_of_birth) / 365.25`), `position`, `sub_position`, `foot`, `height_in_cm`, and `country_of_citizenship`.
  3. **Window inequalities:** valuation rows aggregate match records in `(as_of_date - 365 days, as_of_date]` — half-open, so a match exactly 365 days before the valuation date is excluded and the window covers exactly 365 days; transfer-evaluation rows aggregate match records in `[transfer_date - 365 days, transfer_date - 1 day]` (`game_date < transfer_date`) so appearances after joining the buying club never leak into pre-transfer features.
  4. **Chronological splits:** `train` covers seasons `2017` to `2023`, `validation` is season `2024`, and `test` is season `2025` (expanding-window season folds inside `train + validation` are used for cross-validation in §3.15). Random row-level splits and player-mixed temporal splits into future seasons are forbidden. Every learned statistic (Empirical Bayes positional priors, median height imputers, scalers, K-Means centroids, and supervised estimators) is fit strictly on the training split.
- **Why it matters:** Transfermarkt snapshots span multiple seasons; look-ahead bias would invalidate the undervaluation claims.
- **Needed by:** week 4 (clean, transform).

### 3.5 Data cleaning policy

- **Decide:** the rules for missing values (including when a zero is a real value and when it means missing), outliers, duplicates, and noise: what is dropped, imputed, or capped, and which stage applies each rule.
- **Inputs known so far:** the ingest output is all text (every column is Arrow `string`), so `clean` owns all typing ([ADR-012](ARCHITECTURE.md#adr-012-ingest-stores-source-columns-as-text-typing-happens-in-clean)). The faithful copy of version 679 shows six things. (1) `game_lineups.number` is text, and 25,698 rows hold "-". (2) `clubs.total_market_value` (796 of 796 rows) and `national_teams.coach_name` (124 of 124) are entirely null. (3) `transfers.transfer_fee` and `transfers.market_value_in_eur` use the "700000.000" form, while `players.market_value_in_eur` has no decimals ("1000000"); `clean` must parse both. (4) Empty strings are distinct from null: `game_events.description` has 93,157 and `game_lineups.position` has 3. (5) Nulls per table: appearances 2, club_games 104,884, clubs 1,287, competitions 39, countries 0, game_events 1,730,113, game_lineups 0, games 81,774, national_teams 137, player_valuations 92,973, players 199,373, transfers 129,686. (6) There are no blank lines, CRLF line endings, multi-line values, BOM, or duplicate headers.
- **Decision (2026-10-28, refined 2026-10-29):**
  1. **Explicit schema casting in `clean`:** keep non-integer identifiers as non-null `string` (`appearances.appearance_id` formatted as `"<game_id>_<player_id>"`, `game_lineups.game_lineups_id` as a 32-character hex digest, and competition codes `competition_id`, `domestic_competition_id`, and `player_club_domestic_competition_id` such as `"IT1"` or `"CL"`); cast numeric entity IDs (`game_id`, `player_id`, `club_id`, `player_club_id`, `opponent_id`, `home_club_id`, `away_club_id`, `from_club_id`, `to_club_id`, `current_club_id`) to `int64` (nullable `int64` on optional integer columns such as `number`, `country_id`, `total_clubs`, `stadium_seats`, `attendance`, `height_in_cm`, and league table positions); cast match counts (`minutes_played`, `goals`, `assists`, `yellow_cards`, `red_cards`, `own_goals`, `opponent_goals`, `home_club_goals`, `away_club_goals`, `season`) to `int64` and binary flags (`is_win`, `team_captain`) to `bool`; parse EUR amounts (`player_valuations.market_value_in_eur`, `transfers.transfer_fee`, `transfers.market_value_in_eur`, handling both integer strings and `"700000.000"` decimal strings) to `float64`; slice all date/timestamp strings to their leading 10 characters (`YYYY-MM-DD`) before parsing to `date32` so `players.date_of_birth` (`"YYYY-MM-DD HH:MM:SS"`) parses identically to date-only tables.
  2. **Whitespace, sentinels, and zeros vs. nulls:** strip leading and trailing Unicode whitespace on every string column first (affecting `44,493` trailing `\xa0` non-breaking-space cells in `players.city_of_birth`, `39,104` retained non-sentinel outfield cells, plus `4` in `game_lineups.player_name`), then map empty strings `""` (`3` rows in `game_lineups.position`), `"-"` in `game_lineups.number` (`25,698` rows) and `players.city_of_birth` (`127` raw `"-\xa0\xa0"` cells, `99` on retained outfield rows), and `"-1"` in `competitions.country_id` (`12` international competitions whose `country_name` is null) to null. Preserve `"0"` and `"0.000"` as real numeric zero on match statistics (`goals`, `assists`, `yellow_cards`, `red_cards`, `own_goals`, `opponent_goals`, `is_win`, `team_captain`), where zero means the event did not happen. On `transfers.transfer_fee`, keep `0.0` (`96,085` free transfers and loans) distinct from null (`61,526` undisclosed fees), and filter to `transfer_fee > 0` when building the paid-transfer sample.
  3. **Duplicate check, outlier rules, and `_clean.json` manifest in `clean`:** assert zero duplicate primary keys across all 9 included tables before row filtering (exit 1 if violated); drop `player_valuations` rows with null or `<= 0` `market_value_in_eur` (`1` row in v679, `656,301` to `656,300`); drop `players` rows with null `date_of_birth` (`49` rows) or `position` in `{'Goalkeeper', 'Missing'}` (`6,414` rows, `6,449` unique rows dropped across their union, leaving `43,700` outfield players); drop `appearances` rows with `minutes_played <= 0` (`3` rows, `1,894,350` to `1,894,347`) and cap `minutes_played > 120` at `120` (`3` rows from extra-time stoppage entry overshoot); convert implausible `players.height_in_cm <= 0` or `< 140` (`13` rows, leaving valid heights in `[154, 206]` cm; `112` total nulled cells on retained `players` together with the `99` `city_of_birth` sentinels) to null rather than dropping the player. Across v679, `clean` writes `9` typed Parquet tables (`6,216,263` rows from `6,222,716` input rows, `25,825` nulled cells, about `165` MiB) plus `ml/data/clean/_clean.json` recording `dataset`, `version`, `source_snapshot_sha256`, `cleaned_at` (ISO 8601 UTC with `Z`), `tool_versions` (`pandas`, `pyarrow`), `excluded_tables`, and `tables` keyed by table name (`parquet_file`, `input_rows`, `output_rows`, `dropped_rows`, `capped_rows`, `nulled_cells`, `stripped_cells`, `dropped_columns`, `columns`, and `dtypes`).
  4. **Stage boundary for imputation and error loss:** `clean` writes typed, row-filtered Parquet tables to `ml/data/clean/` without cross-row statistical imputation so train/val/test separation cannot leak. Missing `height_in_cm` (`3,519` retained outfield players after outlier nulling; `4,378` across all `50,149` raw players) is imputed by positional median and missing `foot` (`4,310` retained outfield players; `5,893` across all raw players) is mapped to `"unknown"` inside `transform` and the fitted `sklearn` preprocessor using `train` rows only. To stay aligned with the ordinary-least-squares linear and polynomial specification in [docs/CONTEXT.md](CONTEXT.md) §4, regression models optimize squared error (`MSE` / `RMSE`) on `log10(market_value_in_eur)`, with `MAE` on the log scale and `MdAPE` in EUR reported alongside `RMSE` and `R^2`.
- **Why it matters:** [docs/CONTEXT.md](CONTEXT.md) §3 phase 3 commits to exhaustive treatment of nulls, outliers, and noise, and undocumented rules cannot be defended.
- **Needed by:** week 4 (clean, transform).

### 3.6 Feature engineering

- **Decide:** the derived attributes (for example per-90-minute rates, age from date of birth, remaining contract length), the categorical encoding (for example position), and the scaling, with the fitted transformers stored in the artifact preprocessor.
- **Decision (2026-10-31, partial):** the player's market value from any earlier valuation (for example the previous season's `player_valuations.market_value_in_eur`) is excluded from every feature set. It is point-in-time safe under §3.4, but it would make the regression reproduce the prior valuation, so the residual would measure the change in valuation instead of the gap between performance and price that §3.9, §3.10, and §3.12 rely on. The lower regression `R^2` is an accepted cost ([docs/REPORT_NOTES.md](REPORT_NOTES.md) H-09).
- **Decision (2026-10-31, partial):** the Empirical Bayes prior of the per-90 rate features is grouped by `position` (`Defender`, `Midfield`, `Attack`), not by `sub_position`. Three of the twelve `sub_position` groups hold fewer than `5,500` n90 of exposure in the training seasons, which makes their priors estimates from a handful of events, and the `sub_position` labels drift between seasons. `sub_position` stays in the model sets as a categorical feature, where the training split estimates the offsets, and it is subject to the VIF check of E3. The rate features travel from `transform` to `train` as counts and minutes; the prior, the imputers and the scalers are fitted on the training split only, and the parameters that both stages must agree on (`window_days`, `minutes_floor`, `empirical_bayes_m`, `prior_grouping`, `season_month_start`) are recorded in the transform manifest (`_transform.json`) so `train` reads them instead of hard-coding them.
- **Decision (2026-11-01):** the `FULL` set is fixed as biographical (`age`, `age_sq`, `height_in_cm`, `foot`, `position`, `sub_position`, `country_group`), volume (`minutes`, `apps`, `starts`, `starter_ratio`, `captain_ratio`), Empirical Bayes per-90 rates for `goals`, `assists`, `yellow_cards` and `red_cards`, and team context (`win_rate`, `clean_sheet_rate`, `goals_conceded_per_match`, `uefa_share`, `cup_share`, `league_position`). Two exclusions and four notes follow from the evidence in [docs/REPORT_NOTES.md](REPORT_NOTES.md) H-13 and H-14:
  1. **`league_id` is excluded.** It was the largest single gain in the E1 ladder (`R^2` `0.578` to `0.810`, `RMSE` `0.4337` to `0.2909`), but it is a pricing variable rather than a performance one: with it in the model the undervaluation residual measures the price against the league's typical price instead of the price against performance, which is the same reasoning that excludes prior market value (H-09) and league from `CLUSTER`. The lower `R^2` is accepted for the same reason as in H-09.
  2. **Raw production counts are excluded.** E1b measured `goals`, `assists`, `yellow_cards` and `red_cards` as raw counts alongside the rates: a `0.05%` `RMSE` gain, which does not pay for four more columns. The counts enter only through the rates.
  3. **`apps` is excluded.** E3's VIF pass put it at `15.6`, the redundant middle of the `minutes`/`apps`/`starts` cluster (r `0.90` to `0.92`). `minutes` is the exposure the rates and the `180`-minute floor already use, and `starter_ratio` keeps incumbency.
  4. **`position` is excluded.** E3 showed it is exactly determined by `sub_position`, so the nesting is pure redundancy. The accepted cost is that a novel `sub_position` at live scoring encodes to all zeros with no coarser position behind it.
  5. **The one-hot blocks are left whole.** Their infinite VIF is the dummy trap — each block sums to one under an intercept — not data redundancy, and predictions are unaffected by `drop="first"`.
  6. **`age` is mean-centred before squaring.** `age` and `age_sq` carried VIF `127` through r `0.996`, a polynomial-basis artefact rather than redundant data. `CenteredPolynomial` learns the training mean and substitutes `[age - m, (age - m)^2]` at equal width. The span is unchanged, so the OLS fit and every OLS prediction are unchanged — measured at `1.33e-14`, reproducible on re-run — and the tree models showed deltas of `+0.0002` and `+0.0008` `RMSE` against fold-to-fold variation of `0.0086` and `0.0032`, no measurable preference. The experiment's raw arm bypasses the pipeline's centring step (`center_age=False`) so the comparison stays a genuine before/after rather than a tautology. The centre is a fitted statistic, learned per fold on the training seasons only.

The final `FULL` therefore carries `minutes`, `starts`, `starter_ratio`, `captain_ratio`, `age`, `age_sq`, `height_in_cm`, `win_rate`, `clean_sheet_rate`, `goals_conceded_per_match`, `uefa_share`, `cup_share` and `league_position` as numeric; `foot`, `sub_position` and `country_group` as categorical; and the four Empirical Bayes per-90 rates.
- **Decision (2026-11-01):** `empirical_bayes_m` stays at `5`. E2 and its re-sweep E2b both place the `RMSE` optimum at `m = 20` (H-13), but `m` is measured in 90-minute matches, so `m = 20` is `1,800` minutes of positional prior against a `180`-minute floor: a player at the floor would be estimated `91%` from the prior and `9%` from his own data, against `71%` at `m = 5`. The minutes floor exists precisely to keep emerging squad players and rotation prospects, where undervalued assets tend to be, and heavy shrinkage flattens those rows toward the positional mean. The `RMSE` difference is `0.07%`, which is not decision-relevant. `m = 5` is also the value H-05 measured for the separate next-season `G+A/90` question, so the two findings now agree rather than needing separate constants.
- **Why it matters:** [docs/CONTEXT.md](CONTEXT.md) §3 phase 4 requires it, and the preprocessor is part of the ARCHITECTURE.md artifact contract, so batch and live scoring apply identical transforms.
- **Needed by:** week 4 (clean, transform).

### 3.7 Target transform and polynomial scope

- **Decide:** the log(market_value) regression strategy (transform, back-transform, error scale), and the reduced feature set for the polynomial model with its degree chosen by cross-validation; justify the polynomial model against the linear baseline.
- **Decision (2026-11-02):** the target is `log10(market_value_in_eur)`, fitted by ordinary least squares to match the course scope, and scored as `RMSE` and `MAE` on the log scale with `R^2` and `MdAPE` in EUR reported alongside. `MdAPE` is computed after back-transforming with `10 ** prediction`, floored at `0`, with the floored-row count reported because a log-scale prediction can come back non-positive (`10 ** prediction` is strictly positive in exact arithmetic and never hits the `0` floor on v679, whereas fitting OLS directly on raw EUR produces `5,470` negative EUR predictions — `20.74%` of the `26,373` pooled `2020..2024` validation rows and `50.29%` in the bottom market-value quartile — alongside severe fitted-level heteroscedasticity `R^2 = 0.2080` vs. `0.0057` under `log10`, skewness `4.35` vs. `0.27`, excess kurtosis `38.65` vs. `0.12`, and `MdAPE` `100.0%` vs. `61.22%`; `analysis/residual_diagnostics.py`, E5, [docs/REPORT_NOTES.md](REPORT_NOTES.md) H-16). The polynomial model is justified against the linear baseline by experiment E4: on `POLY_REDUCED` across the five expanding-window folds it beats the linear baseline by `3.1%` mean `RMSE` (`0.4957` against `0.5115`), and the **one-standard-error rule selects degree 2 with the full square-and-interaction expansion** (20 terms) over degree 3 (55 terms), which gains only `0.0028` mean `RMSE`, under half a standard error. The full expansion is what pulls the model into the acceptable band: the interaction-only variant (`0.5028`) falls outside it. Decomposed, the interactions contribute `0.0087` of the `0.0158` total gain over the linear baseline and the marginal squares `0.0070`, so the gain is shared rather than dominated by either. `age_sq` passes through unchanged in every variant, so this run does not speak to whether the explicit square earns its place — that is a question for a squares-only variant, which was not run. Degree 3 does not overfit on this set — accuracy is monotone in degree — so degree 2 is chosen on parsimony, not on degradation.
- **Why it matters:** drives prediction quality and the residual statistics every downstream output (labels, inefficiency analysis, replacements economics) is built on.
- **Needed by:** week 4 (target transform) and week 5 (polynomial degree).

### 3.8 K-Means specifics

- **Decide:** the feature set and scaling, k selection (elbow/silhouette), and cluster validation and stability checks.
- **Decision (2026-10-31, partial):** the cluster feature set excludes market value and league, and includes the Empirical Bayes per-90 rates, `starter_ratio`, minutes, card rates, competition mix and `sub_position`, with the `sub_position` levels below `1%` of the training rows collapsed into `other`. `k` is chosen by the rule in [docs/TRANSFORM_PLAN.md](TRANSFORM_PLAN.md) §6: the candidates are the `k` in `3` to `15` whose silhouette is within 5% of the maximum, at least `0.25` in absolute terms, with no cluster below about 3% of rows, that pass the stability checks (temporal ARI >= 0.5 against a K-Means fitted on the validation season, and mean bootstrap ARI >= 0.8 computed on the intersection of resampled rows); among the candidates the elbow candidate wins if present, otherwise the largest `k`. The smallest candidate is excluded on purpose, because silhouette peaks at small `k` and "within 5% of the maximum" would otherwise resolve to `k = 2`. The chosen `k` will be written here as a constant once E6 runs, and `train` will not re-select it. The scaler (`StandardScaler` against `RobustScaler`) and the cluster feature set are still open until E6 and E7 run.
- **Decision (2026-11-02):** the scaling is **`RobustScaler`**, and **`k = 3`**. E6 under `StandardScaler` produced an empty candidate set: the maximum sampled silhouette anywhere in the sweep was `0.2216`, below the `0.25` floor, which is the conventional boundary for any substantial cluster structure at all. Stability was otherwise strong (temporal ARI `0.935` at `k = 4`, bootstrap `0.903`, no degenerate clusters), so the finding was about the geometry rather than the fit. E7 then re-ran the identical sweep under `RobustScaler`, which uses medians and interquartile ranges instead of means and standard deviations: the maximum silhouette rose to **`0.4142`** at `k = 3`, clearing the floor. `k = 3` passes every gate — silhouette `0.4142`, temporal ARI `0.931`, bootstrap ARI `0.984`, minimum cluster share `7.3%` — and is the only candidate, since `k = 2` is excluded by the `k >= 3` floor and `k = 4` fails both the 5% silhouette band and the 3% share floor. The lesson recorded for the report is that `StandardScaler` was letting the high-variance directions (`minutes`, the competition shares) swallow the structure; the earlier empty result was never a claim about football. `build_preprocessor` keeps `StandardScaler` as its default for the affine regression preprocessors, while `delphos_ml.models._kmeans.fit_ordered_kmeans` explicitly passes `scaler=RobustScaler()` for `CLUSTER`.
- **Why it matters:** cluster assignments feed the archetype explorer and the replacement-similarity metric.
- **Needed by:** week 4 (feature set and scaling) and week 5 (k selection).

### 3.9 Undervalued/overvalued label definition

- **Decide:** the threshold rule (e.g. a residual percentile) that labels a player undervalued or overvalued, and out-of-fold label derivation — labels derived from regression residuals must be generated on held-out folds.
- **Decision (2026-11-03):**
  1. **Champion regressor and sign convention:** both Multiple Linear Regression (`FULL`) and degree-2 Polynomial Regression (`POLY_REDUCED`) are trained and compared, while the canonical `fair_value_eur` and valuation residual come from the regressor with the lowest expanding-window cross-validated `RMSE` — **OLS Multiple Linear Regression on `FULL`** (`0.4354` mean `RMSE` on the VIF-pruned `FULL` set that ships, `0.4337` prior to dropping `apps` in E3, vs. `0.4957` for degree-2 polynomial on `POLY_REDUCED`, which omits team context, `sub_position`, and Empirical Bayes shrinkage). The valuation gap (fair-value surplus) is defined as `residual_log10 = predicted_log10_value - log10_market_value`, so positive values mean fair value exceeds market price (`undervalued`) and negative values mean market price exceeds fair value (`overvalued`).
  2. **Strict chronological out-of-fold (OOF) derivation:** to satisfy §3.4 without future leakage, `train` computes `residual_log10` across `train` seasons `2018` to `2023` (`31,714` rows, `86.07%` of `train`) using six forward-only expanding windows (`2017 -> 2018`, ..., `2017..2022 -> 2023`), refitting a fresh `FULL` preprocessor and OLS estimator on `2017..s-1` for each season `s`. Season `2017` (`5,133` rows) has no earlier training season in `2017..2025`; it anchors fold 1, is excluded from OOF quantile estimation and classifier training, and carries `residual_source = "in_sample_anchor"` in batch outputs (versus `"oof"` on `2018..2023`, `"validation"` on `2024`, and `"test"` on `2025`, where `2024` and `2025` are scored by the full-`train` `2017..2023` estimator).
  3. **Quartile thresholds, binary target, and rejected alternatives:** the 25th and 75th percentiles are computed once on the `31,714` pooled `train` OOF residuals (`analysis/classification_selection.py`, E8; [docs/REPORT_NOTES.md](REPORT_NOTES.md) H-15): **`q25 = -0.3450`** (`fair_value / market_value <= 0.4519`) and **`q75 = +0.2735`** (`fair_value / market_value >= 1.8772`). Every row receives a three-zone `valuation_status` (`"undervalued"` if `residual_log10 >= q75`, `"overvalued"` if `residual_log10 <= q25`, `"fair"` otherwise) plus the binary one-vs-rest target `is_undervalued = (residual_log10 >= q75)`. Applied unchanged to held-out `2024` validation (`4,981` rows), the thresholds yield `22.73%` `undervalued`, `53.06%` `fair`, and `24.21%` `overvalued`. Rejected alternatives: (a) *fixed hand-picked `log10` cutoffs* (e.g. `±0.30`), rejected because arbitrary EUR ratios are uncalibrated to the model's empirical error dispersion (`std = 0.4472`) and nominal-inflation offset (`mean = -0.0434`); (b) *per-season `q25`/`q75` quartiles*, rejected because scoring a future season (`2024`, `2025`, or live `POST /players/what-if`) cannot know that season's residual quantiles in advance without leaking target valuations; (c) *median split (`r >= 0`)*, rejected because noise near `r = 0` labels fair-priced players as bargains; and (d) *dropping the middle `50%` `"fair"` rows to train a pure `undervalued` vs. `overvalued` classifier*, rejected because deployment and live scoring must classify all players, not a pre-filtered extreme subset.
- **Why it matters:** leakage through in-fold labels would inflate the valuation-status findings the app surfaces and the grader evaluates.
- **Needed by:** week 5 (train).

### 3.10 Classification model design

- **Decide:** the features, class-imbalance handling, hyperparameter search, and metrics for the Random Forest and Decision Tree classifiers, and how they use the labels from 3.9.
- **Decision (2026-11-03):**
  1. **Features, training sample, imbalance handling, and rejected alternatives:** both `DecisionTreeClassifier` and `RandomForestClassifier` consume the `FULL` feature set through a dedicated `FULL` preprocessor fitted on the `31,714` OOF-labelled `train` rows (`2018..2023`), predicting the binary target `is_undervalued` (`1` when `residual_log10 >= q75`, ~25% positive prevalence). Market value and `league_id` stay excluded so the trees discover observable sporting and biographical pockets of systematic market discounting rather than memorizing `fair_value - market_value`. Class imbalance (`25%` vs. `75%`) is handled via `class_weight="balanced"`; rejected alternatives were *unweighted trees (`class_weight=None`)* (rejected because `0.5` probability predictions collapse toward the majority non-undervalued class, degrading `F1` and `Balanced Accuracy`) and *synthetic oversampling (SMOTE)* (rejected because interpolating one-hot `sub_position` / `country_group` vectors produces non-physical player rows without improving tree split ordering). Note that in batch `player_predictions.parquet`, `dt_undervalued_*` and `rf_undervalued_*` on `2018..2023` (`split == "train"`, `residual_source == "oof"`) are **in-sample** tree scores because the final classifiers fit on those `31,714` OOF-labelled rows; classifier generalization is evaluated strictly via expanding-window CV (`E8` / §3.15) and held-out `2024` / `2025` splits.
  2. **Leak-free hyperparameter selection and metrics:** experiment E8 (`analysis/classification_selection.py`) swept `max_depth` and `min_samples_leaf` across five expanding-window outer folds (`validate 2020..2024`, never reading `2025` `test`), recomputing fold-internal OOF residuals, fold-internal `q75` thresholds, and fold-scoped preprocessors inside every outer fold. Primary selection metric is **`PR-AUC`** (`average_precision_score` on the positive `is_undervalued` class, naive baseline `0.2323`) with the **one-standard-error rule** favoring simpler trees (smaller `max_depth`, larger `min_samples_leaf`); `ROC-AUC`, `F1`, `Precision`, `Recall`, and `Balanced Accuracy` are reported alongside:
     - **Decision Tree (`DecisionTreeClassifier`):** **`max_depth = 10`, `min_samples_leaf = 100`, `class_weight = "balanced"`, `random_state = 20261103`** (`PR-AUC = 0.3291`, within 1 SE of `0.3351 ± 0.0096`; `ROC-AUC = 0.6333`, `F1 = 0.4092`, `Balanced Accuracy = 0.5979`).
     - **Random Forest (`RandomForestClassifier`, champion classifier):** **`n_estimators = 300`, `max_depth = 14`, `min_samples_leaf = 5`, `class_weight = "balanced"`, `random_state = 20261103`** (`PR-AUC = 0.3959`, within 1 SE of `0.4097 ± 0.0146`, a `+70.4%` lift over the prevalence baseline and `+20.3%` over Decision Tree; `ROC-AUC = 0.6904`, `F1 = 0.4372`, `Balanced Accuracy = 0.6305`).
- **Why it matters:** [docs/CONTEXT.md](CONTEXT.md) §4.1 commits to testing both, and the label rule alone defines neither the model nor how the two are compared.
- **Needed by:** week 5 (train).

### 3.12 Statistical inefficiency demonstration

- **Decide:** which hypothesis test(s) are run, the reported statistic and significance, and the population they cover — transfer-fee vs predicted-value residuals.
- **Decision (2026-11-03):**
  1. **Population and primary quantity:** the test population is the `5,325` paid outfield transfers (`transfer_fee > 0`, seasons `2017..2025`, `>= 180` trailing pre-transfer minutes in `[transfer_date - 365 days, transfer_date - 1 day]`) scored in `ml/data/train/transfer_predictions.parquet`, evaluated separately across three scopes so pre-`test` discovery and held-out replication stay distinct: `train_validation` (`2017..2024`, `4,396` transfers), held-out `test` (`2025`, `929` transfers), and `all` (`2017..2025`, `5,325` transfers). The tested random variable is the log-scale fee-to-fair-value gap `fee_minus_fair_log10 = log10(transfer_fee) - linear_log10_pred` (`> 0` means the buying club paid above sporting fair value; `< 0` means the buying club captured a sporting bargain). Pre-transfer valuation status (`undervalued` if `pre_res >= q75`, `overvalued` if `pre_res <= q25`, `fair` otherwise, where `pre_res = linear_log10_pred - log10(pre_transfer_market_value)`) uses the frozen §3.9 `train` OOF cutoffs (`q25 = -0.3450`, `q75 = +0.2735`) without touching `transfer_fee`.
  2. **Six-test paired parametric + non-parametric battery with Holm-Bonferroni FWER control:** within each scope, `delphos_ml.evaluation.run_inefficiency_tests` executes six two-sided tests and adjusts all six p-values via step-down **Holm-Bonferroni** at family-wise `alpha = 0.05` (`reject_null = (p_value_holm < 0.05)`), reporting standardized effect sizes and EUR ratios alongside every test ([docs/REPORT_NOTES.md](REPORT_NOTES.md) H-17):
     - `one_sample_t_fee_vs_fair` (`t`, `cohen_d`) and `wilcoxon_fee_vs_fair` (`W`, `matched_rank_biserial`): test whether global paid transfers systematically depart from sporting fair value (`0.0`). Rejected across all three scopes (`train_validation`: `t = 7.10, p_holm = 2.87e-12`, `W = 4,140,696, p_holm = 6.19e-16, matched_rank_biserial = +0.1431`, median `+0.0816` or `1.207x` fair value; `test` `2025`: `t = 3.30, p_holm = 0.0024`, `W = 188,529, p_holm = 0.0024, matched_rank_biserial = +0.1272`, median `+0.0738` or `1.185x`; `all`: `t = 7.83, p_holm = 1.16e-14`, `W = 6,096,177, p_holm = 2.39e-18, matched_rank_biserial = +0.1402`, median `+0.0797` or `1.201x`).
     - `mann_whitney_undervalued_vs_overvalued` (`U`, `rank_biserial`) and `welch_t_undervalued_vs_overvalued` (`welch_t`, `cohen_d`): test whether clubs anchor transfer fees to subjective pre-transfer Transfermarkt valuations rather than correcting toward sporting fair value. Strongly rejected across every scope (`all`: `957` `undervalued` transfers trade at median `-0.5112` `log10` or `0.308x` fair value vs. `1,682` `overvalued` transfers at `+0.5660` `log10` or `3.681x` fair value; `U = 44,875, p_holm < 1e-300, rank_biserial = -0.9442`; `welch_t = -66.03, p_holm < 1e-300, d = -2.70`; replicated on `2025` `test`: `U = 819, p_holm = 1.85e-58`, `welch_t = -28.10, p_holm = 1.04e-83`).
     - `kruskal_big5_vs_non_big5` (`H`, `epsilon_squared`): tests structural overpayment by Big-5 buying leagues (`GB1`, `ES1`, `IT1`, `L1`, `FR1`) vs. the remaining 9 covered leagues. Rejected in every scope (`all`: `2,825` Big-5 purchases at median `+0.2906` / `1.953x` fair value vs. `2,500` non-Big-5 purchases at `-0.2215` / `0.601x`, a `2.89x` ratio; `H = 847.38, p_holm = 1.08e-185, epsilon^2 = 0.1592`; `2025` `test`: `423 Big-5 vs. 506 non-Big-5 purchases, ratio 2.93x; H = 142.71, p_holm = 2.73e-32, epsilon^2 = 0.1538`).
     - `kruskal_across_clusters` (`H`, `epsilon_squared`): tests whether fee gaps differ across the 3 K-Means tactical archetypes. Rejected with negligible effect size on `train_validation` (`H = 8.13, p_holm = 0.0171, epsilon^2 = 0.0019`) and `all` (`H = 7.93, p_holm = 0.0190, epsilon^2 = 0.0015`), and **not rejected** on held-out `2025` `test` (`H = 0.70, p_holm = 0.7046, epsilon^2 = 0.0008`), confirming that market inefficiency is driven by valuation anchoring and buyer-league tier rather than on-pitch tactical role.
  3. **Rejected alternatives and Parquet contract:** rejected alternatives were (a) *testing raw EUR differences `transfer_fee - fair_value_eur` with parametric t-tests only*, rejected because EUR residuals have kurtosis `> 38` so a handful of `€100M+` transfers dominate the mean; (b) *unadjusted p-values across multiple subgroup tests*, rejected to control family-wise false positives; and (c) *testing `transfer_fee - pre_transfer_market_value` alone*, rejected because fees closely track Transfermarkt quotes (`median = -0.039` `log10`), hiding the inefficiency relative to sporting output. `evaluate` writes `ml/data/evaluate/inefficiency_analysis.parquet` (`18` rows): `scope`, `test_id`, `hypothesis`, `statistic_name`, `statistic`, `p_value`, `p_value_holm`, `alpha`, `reject_null`, `n_primary`, `n_secondary` (nullable), `effect_size_name`, `effect_size`, `primary_median_log10`, `secondary_median_log10` (nullable), and `median_eur_ratio`.
- **Why it matters:** this accepts the responsibility stated in ARCHITECTURE.md: the pipeline `evaluate` stage emits the `inefficiency_analysis` output and the analysis scripts present the demonstration; minimal acceptance is at least one hypothesis test with reported statistic and significance, presented by the analysis scripts and summarized in the app.
- **Needed by:** week 6 (evaluate: inefficiency analysis).

### 3.13 Replacements algorithm

- **Decide:** the "elite asset" definition/threshold, the athletic-equivalence similarity metric (cluster membership vs feature-space distance; which features and weights), and the ranking and tie-break rules.
- **Decision (2026-11-03):**
  1. **Elite-asset definition and catalog-wide precomputation:** a player-season is flagged `is_elite_asset = (market_value_eur >= elite_mv_threshold_eur[position])`, where `elite_mv_threshold_eur` is the **75th percentile (`P75`) of `market_value_eur` per `position` fitted strictly on the `train` split (`2017..2023`, `36,847` rows)**: **`Attack = €6,000,000`**, **`Midfield = €6,000,000`**, and **`Defender = €4,000,000`**. While `is_elite_asset` identifies the high-cost scouting targets emphasized in [docs/CONTEXT.md](CONTEXT.md) §2 (`1,764` elite players out of `5,522` active players in `2025`), `evaluate` precomputes replacement rankings for **every** player in the active latest season (`max(season) = 2025`, `5,522` rows) so `GET /players/{id}/replacements` serves the entire published catalog uniformly.
  2. **Athletic-equivalence and economic-profitability gates:** for a target player `t` in the active season, a candidate `c != t` in the same active season qualifies if and only if all four gates hold:
     - **Tactical archetype gate:** `c.cluster_id == t.cluster_id` (same `k = 3` K-Means archetype) **and** `c.position == t.position` (`Attack`, `Midfield`, or `Defender`, preventing cross-line mismatches inside high-exposure clusters).
     - **Feature-space radius gate:** Euclidean distance `d(t, c) = ||x_t - x_c||_2` in the 18-column `RobustScaler`-transformed `CLUSTER` space (`bundle.cluster_preprocessor`, uniform unit weights after IQR scaling, zero market-value or league columns) satisfies `d(t, c) <= distance_ceiling[cluster_id, position]`, where `distance_ceiling` is the **25th percentile (`P25`) of same-season, same-`(cluster_id, position)` pairwise Euclidean distances fitted strictly on `train`** (ranging from `1.4526` for `2:Defender` to `1.8532` for `0:Attack`, i.e., `similarity_score >= 0.35..0.41`).
     - **Cost-reduction gate:** `c.market_value_eur <= 0.80 * t.market_value_eur` (at least a `20%` market-value discount).
     - **Non-overvaluation gate:** `c.valuation_status != "overvalued"` (`c.residual_log10 > q25`, accepting `"undervalued"` and `"fair"` candidates while rejecting players priced above sporting output).
  3. **Deterministic ranking, unpadded output, and shortfall codes:** qualifying candidates are ranked by **ascending `euclidean_distance`** (equivalently descending bounded `similarity_score = 1 / (1 + d)` in `(0, 1]`), breaking ties by **descending `candidate_residual_log10`** (greater fair-value surplus), and finally **ascending `candidate_player_id`**. At most `3` rows (`rank` `1..3`) are emitted per target and **never padded**. Every active player has one row in `replacement_targets.parquet` (`5,522` rows) recording `qualifying_count` (`0..3`) and `shortfall_reason` (`null` when `qualifying_count == 3`, otherwise the earliest binding bottleneck among `"no_same_cluster_and_position_peer"`, `"no_peer_within_athletic_distance"`, `"no_peer_below_cost_ceiling"`, `"no_non_overvalued_peer"`, and `"fewer_than_three_qualifying_peers"`), while `replacements.parquet` (`15,801` rows on v679) stores the `0..3` ranked candidates. On active season `2025`, **`98.70%` (`1,741 / 1,764`) of elite assets** (`99.55%` with `>= 1`) and **`93.68%` (`5,173 / 5,522`) of all players** obtain 3 qualifying replacements, with a median `84.8%` market-value discount (`€9.85M` median savings) on elite targets ([docs/REPORT_NOTES.md](REPORT_NOTES.md) H-18). Rejected alternatives: (a) *unconstrained K-NN padding that always emits 3 rows*, rejected because it violates ARCHITECTURE.md §5 and recommends more expensive or tactically distant players; (b) *cosine similarity in `FULL`*, rejected because `FULL` includes biographical `country_group` and age-curve pricing terms rather than pure on-pitch role; and (c) *requiring strictly `undervalued` (`top 25%`) candidates only*, rejected because on `2024` validation calibration it cut elite 3-replacement coverage by ~9 percentage points by rejecting tactically identical `"fair"`-priced bargains already costing `<= 80%` of the target.
- **Why it matters:** implements the `GET /players/{id}/replacements` contract from ARCHITECTURE.md — candidates are computed at publish and ranked, with up to 3 per target: exactly 3 when 3+ qualifying candidates exist, otherwise fewer with an explicit "no qualifying replacement" reason, never padded.
- **Needed by:** week 6 (evaluate/publish: replacements).

### 3.15 Evaluation and cross-validation plan

- **Decide:** metrics (e.g. R2/RMSE/MAE on the transformed target), the CV scheme, and the comparison of data-mining schemes ([docs/CONTEXT.md](CONTEXT.md) §6, week 7).
- **Decision (2026-11-03):**
  1. **Cross-validation and held-out protocol:** supervised schemes are evaluated across three leak-free scopes stored in `ml/data/evaluate/model_metrics.parquet` (`72` rows): (a) **`cv_5fold`**, five chronological expanding-window season folds inside `train + validation` (`2017..2019 -> 2020`, ..., `2017..2023 -> 2024`, `26,373` pooled validation rows), where each fold fits its own `FULL` / `POLY_REDUCED` preprocessors, its own inner chronological OOF residuals and `q75` cutoff, and its own estimators on `season < val_season`, reporting fold mean and standard error `se`; (b) **`validation`** (`2024`, `4,981` rows), scored by the `2017..2023` `train` suite; and (c) **`test`** (`2025`, `5,522` rows), evaluated strictly once read-only with all parameters frozen. K-Means (`k = 3`, `RobustScaler`) is evaluated on `train` (`36,847`), `validation` (`4,981`), and `test` (`5,522`) via sampled `silhouette` (`n <= 5,000, random_state = 42`), `calinski_harabasz`, `davies_bouldin`, and `min_cluster_share`.
  2. **Empirical comparison across all five KDD schemes on v679 ([docs/REPORT_NOTES.md](REPORT_NOTES.md) H-18):**
     - **Regression (`RMSE_log10` primary, plus `MAE_log10`, `R^2_log10`, `MdAPE_eur`):** Multiple Linear OLS on `FULL` beats degree-2 Polynomial OLS on `POLY_REDUCED` in every scope — `cv_5fold`: `RMSE = 0.4354 ± 0.0041` (`MAE = 0.3460`, `R^2 = 0.5727`, `MdAPE = 61.19%`) vs. `0.4957 ± 0.0068` (`MAE = 0.4065`, `R^2 = 0.4462`, `MdAPE = 70.98%`); `2024` `validation`: `0.4369` (`R^2 = 0.5833`, `MdAPE = 59.73%`) vs. `0.5119` (`R^2 = 0.4279`); held-out `2025` `test`: **`0.4562`** (`MAE = 0.3585`, `R^2 = 0.5613`, `MdAPE = 59.82%`) vs. **`0.5163`** (`R^2 = 0.4381`, `MdAPE = 70.20%`). While degree-2 polynomial improves `POLY_REDUCED` over degree-1 linear on the same 5 numeric features (`0.4957` vs. `0.5115`, E4), breadth of team-context, positional, and Empirical Bayes features in `FULL` outweighs quadratic curvature on a restricted subset by `0.060` `log10` `RMSE` across all splits.
     - **Classification (`PR-AUC` primary, plus `ROC-AUC`, `F1`, `Balanced Accuracy`, `Precision`, `Recall`):** 1-SE `RandomForestClassifier` outperforms 1-SE `DecisionTreeClassifier` in every scope — `cv_5fold`: `PR-AUC = 0.3959 ± 0.0164` (`ROC-AUC = 0.6904`, `F1 = 0.4372`, `BalAcc = 0.6305`) vs. `0.3291 ± 0.0099` (`ROC-AUC = 0.6333`, `F1 = 0.4092`, `BalAcc = 0.5979`); `2024` `validation`: `PR-AUC = 0.3584` (`ROC-AUC = 0.6873`, `F1 = 0.4228`) vs. `0.3044` (`ROC-AUC = 0.6246`); held-out `2025` `test`: **`PR-AUC = 0.3657`** (`ROC-AUC = 0.6895`, `F1 = 0.4131`, `BalAcc = 0.6239`) vs. **`0.2941`** (`ROC-AUC = 0.6254`, `F1 = 0.3882`).
     - **Clustering (`K-Means`, `k = 3`, `RobustScaler`):** structure generalizes cleanly across time without refitting — `train` `silhouette = 0.4087` (`DB = 0.9941`, `min_share = 7.27%`), `2024` `validation` `silhouette = 0.4192` (`DB = 0.9517`, `min_share = 8.13%`), and held-out `2025` `test` **`silhouette = 0.4176`** (`CH = 2,843.4`, `DB = 0.9612`, `min_share = 9.11%`).
- **Why it matters:** this is the graded evidence that the chosen models earn their place; it feeds the evaluate stage and the analysis scripts.
- **Needed by:** week 7 (evaluate).
